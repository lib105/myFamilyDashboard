# 采购需求问答与商品搜索（仅京东）

> 淘宝及天猫商品搜索已按用户要求取消。相关浏览器采集器、详情核价工作和跨平台搜索入口已移除。该文件名及历史视图类型保留，以免破坏已有记录。

## 当前功能

输入 `我想买牛奶` 或 `在京东找自行车`，助手逐轮确认尚缺的信息：

1. 牛奶：冷藏鲜奶 / 常温；自行车：山地 / 公路 / 通勤 / 儿童。
2. 品牌，可用快捷项或输入 `品牌：你的品牌`。
3. 牛奶的容量与包装数量（如 `200ml×24盒`）；自行车的型号/尺码（如 `RC120 M码700c`）。
4. 每件/每箱的展示价预算（如 `100元以内`、`1000-3000元`、`预算不限`）。

已经说清楚的信息不重复询问。可明确选择“不限”，或点击 **先直接搜** 跳过尚未确认的条件。
点击 **取消采购** 或清空对话会取消未完成的需求，不触发浏览器。
天气、视频、任务等独立问题不会被当作品牌/规格答案。

确认后**仅搜索京东**，优先页面自营标识和店名标注旗舰店的结果。
店名文本不等于应用独立核验的官方认证。品牌、型号、轮径、尺寸、容量、多箱数量及预算仍会核对和标注。
价格和优惠保留原文，不叠券、不猜测遮挡价，不自动领券、加购物车或下单。

## 淘宝/天猫的关闭边界

- 新采购请求只包含 `site_jd`。
- Agent 的 `usesBrowserSite` 权限不再包含淘宝；工具参数中也不提供淘宝/天猫。
- 明确要求淘宝/天猫时，聊天直接说明该平台已取消，不调用模型或浏览器来尝试恢复。
- 服务端白名单和操作白名单拒绝相关 `siteId`，即使客户端修改图谱或直接 POST API 也不会执行。
- 淘宝的搜索 DOM 采集器及未完成的详情核价代码已移除。
- 不再生成或展示新的跨平台比价表格。当前结果界面只展示京东商品。

## 已有记录与进行中的问答

不会清空已有商品快照、对话或其他家庭数据。

- 历史双平台结果保留原始记录；当前视图提示包含已停用平台，并只展示京东部分。
- 仅淘宝的历史记录不会自动替换成一次京东搜索。
- 继续旧的双平台 collecting 问答时，移除已停用站点，明确提示后仅查询京东。
- 旧的淘宝-only collecting 请求会取消，不静默改为京东。
- 采购活动 ID 属于当前聊天记录；刷新后只恢复 collecting 问答，不自动重跑已经执行的浏览器工作。

`BrowserSite(site_taobao)` 保留为 disabled 的历史来源实体，而不是可用浏览器入口。
少量纯历史 URL/结果规范化逻辑保留用于读取既有数据，不包含网络或浏览器操作。

## 本体模型

`ShoppingRequest` 表示一次采购意图和确认过程，不是订单。
对需要追问的字段，`null` 表示尚未回答，`不限` 表示用户明确不限制；预算用 `budgetSpecified` 区分未回答和明确无上下限。

```text
collecting → ready → searching → completed / partial / failed
collecting → cancelled

BrowserTaskRun —fulfillsShoppingRequest→ ShoppingRequest
BrowserTaskRun —targetsSite→ BrowserSite
BrowserTaskRun —executedByAgent→ Agent
```

京东报价快照和采集时间仍保存在 BrowserTaskRun 中，不覆盖原有模拟 PriceOffer / Promotion。
当前为受信任家庭的本地存储设计，不是多租户权限隔离或防篡改的服务端审计系统。

本方法基于 [ontology-building](https://github.com/mgillett43/ontology-skills) by Mark Gillett，遵循 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)，并按当前应用需求作工程化适配。

## 服务端

继续使用 `POST /api/ego-browser/search-products`，仅接受 `siteId: "site_jd"` 与 `query`。
客户端不能提交浏览器 URL 或脚本。视频搜索、家庭健康、任务和其他模块不受此变更影响。
生产部署更新代码后重启桥接服务；Vite 开发环境会跟踪站点配置变化。

验证包括：默认仅京东、需求追问保留、淘宝/天猫聊天与 HTTP 拒绝、篡改客户端权限不能恢复平台、旧问答迁移以及历史快照不删除。

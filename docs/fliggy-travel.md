# 飞猪旅行查询分流

## 服务端配置

仅在服务端环境变量中设置 `FLYAI_API_KEY`，或在项目根目录的 `.env.fliggy.local` 中设置（已被 Git 忽略）。文件权限建议为 600；不要使用 VITE_ 前缀，不要把密钥写入源码或前端存储。

飞猪官方 CLI 运行包需在每台开发机/部署服务器上单独配置到 `server/lib/flyai-bundle.cjs`。请从可信的官方发行渠道获取，核对来源和使用许可后私下部署；该第三方文件可能包含内置凭据，已加入 Git 忽略规则，不随仓库发布。全新克隆后，未配置此文件时不能执行真实旅行查询；单元测试使用注入的 CLI 结果，不需要该文件。

本地 Vite 与独立桥接服务均使用 `server/fliggyBridge.js`。部署后需重启服务进程。生产 API 需继续通过已认证的同源代理提供，不能公开暴露付费调用额度。

## 查询路径

聊天 → 本地确定性识别 → `/api/fliggy/search` → 官方 CLI/MCP。

| 需求 | 官方 CLI 命令 |
| --- | --- |
| 机票/航班 | search-flight |
| 火车票/高铁 | search-train |
| 酒店/住宿 | search-hotel |
| 景点门票 | search-poi |
| 未指定品类的综合旅行需求 | ai-search |

原来的 fliggy-fast-search 关键词搜索不再用于上述垂直查询。
前端与服务端均校验需求；query 中的明确品类优先于类型提示，不能把航班需求改成酒店。
一次包含多个品类时先请用户拆分查询。交通查询需出发地、目的地、日期；缺失会追问，不猜测也不默认查酒店。
相对日期按 Asia/Shanghai 解析。酒店/景点可通过工具参数明确提供目的地城市，文本规则未识别城市时会追问。

指定日期支持 `2026-10-25`、`2026/10/25`、`2026年10月25日`、`10月25号`、`10/25`、`10-25`，可放在航线前后。无年份按当前中国日历年份解释；如果已过期会追问年份，不静默跳到明年。非法日期、已过期日期和参数与问题的日期冲突会被拒绝。
机票/火车票使用 `--dep-date`；明确往返/返回且给出第二日期时传 `--back-date`。酒店需同时给出入住与退房日期，分别传 `--check-in-date` 和 `--check-out-date`，退房必须晚于入住。当前景点垂直接口不支持游玩日期核价，不能将无日期门票价冒充指定日票价。

示例：
- 飞猪查明天北京到上海的航班
- 飞猪查明天北京到上海的高铁
- 飞猪上海迪士尼门票
- 飞猪杭州西湖酒店
- 飞猪查10月25日从大连到三亚的机票
- 飞猪查北京到上海的高铁，2026年10月25日出发
- 飞猪查10月25日入住10月28日退房杭州酒店

结果保留接口中的价格、交通班次、站点、时间和舱位/座席；缺价不补价。
聊天及卡片同步展示查询日期、各行程/中转航段的完整出发和到达日期时间（跨天日期不丢失）、机场/车站、航站楼、舱位/席别及历时。缺时间/站点明确写“未返回”；绝不以查询日期冒充接口的实际出发日期。时间按接口当地时间原文展示，不做未经证实的时区换算。业务错误、空结果和异常结构不触发其他品类兜底，不将酒店卡片当航班。展示价格不保证库存或结算价，不自动订票、付款。

## 对话上下文

旅行查询的结构化条件保存在当前聊天的 assistant 消息元数据 `fliggyContext` 中，不放入共享知识图谱。刷新会话后可继续追问，清空聊天或独立会话不会继承其他人的行程。对旧消息没有元数据的情况，可从最近的明确旅行提问恢复条件。

例如：先查“10月25日大连到三亚机票”，再问“再查查同日的酒店”，继承目的地三亚与10月25日入住，不误用出发地大连，也不误解成今天。缺退房日期只追问退房日期/住几晚；接着回答“住两晚”或“10月27日退房”即可查询。明确的新城市/日期覆盖旧值；无关聊天之后不自动复用旧行程。该关联使用本地确定性规则，不增加大模型调用。
